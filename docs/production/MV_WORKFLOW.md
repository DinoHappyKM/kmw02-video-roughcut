## 1. 定位與來源

技能1是既有「多機訪談剪輯」（含雙機）流程；技能2處理歌曲帶動的情緒、敘事與表演。共用媒體保護、來源追蹤和已確認的繁體字幕／聲音品質規則，MV 的決策順序以本文件為準。

使用者提供指定音樂，以及情緒情境片段或保留原聲的初剪。原始媒體維持原位，初剪另存工作版本。先辨識獨立素材與合併初剪；後者的切鏡、疊化、黑場與混合聲音都可能已烘焙，不能宣稱可還原成原拍鏡次。

歌曲檔要先判讀是完整混音、主唱分軌還是伴奏；分軌需確認時長、起點與聲道，不能直接把主唱分軌當完整歌曲。檔名「無字幕」也可能含可提取字幕軌，先檢查實際媒體。

## 2. 兩項前置確認

### 交付與操作範圍

交付為複選，採自然語言或能真正複選的表單，不用單選題冒充複選：

- MP4：供直接觀看。
- ChatCut：工程／時間線；只在使用者明確選擇 ChatCut 或已建立該工具任務時操作。
- DaVinci DRT：檔案交付，由使用者自行匯入。
- 其他指定交接格式。

分開記錄是否允許助手匯入驗證、播放或另渲染驗證片。選多種產物不等於允許操作所有應用程式；選 DRT 不等於另做 MP4 或替使用者匯入現有工程。

既有偏好只作提示；新作品／明確重測時請使用者確認本次複選。若本次已明確指定產物與操作方式，直接沿用，不重問。

原生 DRT 需要 Resolve 實際建立並匯出。選用時先說明必要製作步驟與獨立工程安排。無法隔離或原生匯出時先報告具體限制，交由使用者選替代方式，不能把 XML 改副檔名當 DRT，也不能為完成格式而擅自擴大現有工程操作。

### 剪法確認

先記錄 A／B／C 偏好及希望觀眾看完留下的感受。讀完素材後通常提出 2～3 組有證據支持的方案，每組包含：

1. 跟著誰、觀眾在乎什麼，以及情緒從哪裡走到哪裡。
2. Hook 畫面／聲音與吸引力；音樂何時進入。
3. 中段主結構、資訊揭露、累積、呼吸與人物反應。
4. 結尾落點、開放／封閉程度，以及與 Hook 的呼應。
5. 必要口白、放置理由、字幕及歌曲主從關係。
6. 現有素材能完成什麼、缺什麼、補拍或替代方式。
7. 全曲或節選、預計長度／畫幅與主要取捨。

使用者選定並確認具體方案後才進入剪輯。助手說「我會採 A+C」是提案或進度告知，不代表已獲確認。沉默、逾時、同意整理規則、前版技術驗收、泛稱「開始」都不能代替本輪剪法確認。若使用者已明確說「照方案 B 做 DRT」，則已有對應授權，直接執行。

## 3. 創作原則

### 結構與情緒

A 三幕劇處理故事發展，B 懸疑反轉處理資訊揭露，C 捧高、小幅打落再累積處理期待與投入。它們可組合，並非所有 MV 必須三選一。表演型、情緒型或視覺概念型也可成立，不為分類補造事件。

B 的每次反轉要有鋪陳與揭露，改變觀眾的理解；次數由歌曲與素材決定。C 要有值得相信的獲得與停留，最後追求最深的情緒結果，不強制悲劇或更大的反轉。

人物、表情、動作與停頓是內容證據；字幕只能補助，不能只讀字幕就宣稱看懂表演。觀察、推測與待確認內容分開，歌詞或關係不明時不自行補造。

### 音樂與畫面

同時分析歌詞含義、演唱語氣、編曲、樂句、段落、間奏及停頓。大段落參考歌曲輪廓，個別剪點也尊重表演與觀眾理解時間，不機械逐拍剪。高潮後保留反應，間奏保留呼吸。

歌詞與畫面可直接對應、情緒對應，或有依據地反差對應；不要求逐字照演。重複副歌可以演變，也可以有目的地重複。先找一個可記住且能發展意義的視覺元素，比堆疊無關漂亮鏡頭更有選片依據。

### 轉場必須對齊音樂踩點

新增或調整鏡頭轉場時，先找音樂實際的重拍、節奏重音或樂句落點，再決定畫面切換的位置。硬切以切換影格對拍；疊化通常以中點、動態轉場以視覺換手或動作重心對拍，不能只把特效開始時間貼在拍點就算完成。

先聽歌並查看波形建立拍點標記，確認歌曲進入時間與局部速度變化。時間換算須含前置 hook、歌曲起點、音樂剪接及速度設定；自動 BPM／節拍偵測只作候選，不能用固定間隔替代聽感。

每個新增轉場在剪輯決策中記錄：音樂踩點、對應成片時間、轉場範圍／視覺重心、最近影格與對拍誤差。受影格格線限制時取最接近影格，並核對實際轉場區段的聲畫。若表演完整性或資訊理解需要偏離，先在提案中說明並取得使用者接受。

踩點決定合適的轉場落點，不要求每拍切換，也不為了踩點增加無意義特效。這次新增的是後續製作規則，未回頭重剪已確認的作品；新增規則的實際節奏效果仍待下一次有轉場需求時驗收。

### Hook、結尾與 callback

三種入口：情境／懸念先行再進音樂；重要片段的局部預演；另錄口白或對嘴演出。第三種只在選用時釐清對嘴的是歌曲還是口白，不默認補錄、生成或改嘴型。

Hook 與結尾配對設計，呼應可用畫面、物件、動作、台詞、聲音或人物選擇。優先有意義的呼應，不強制重播開頭；不為規則傷害作品。偏好開放式結局時，讓情緒有落點，事件結果可留白。

重複同一句 hook 台詞時，具體列出開頭的語境、結尾的新動作／關係變化，以及觀眾如何看出差異。讓台詞出現時，畫面正好承接其意義；不要把較早發生的端杯等動作，當作數十秒後看手機畫面已有的呼應。

### 口白與字幕

逐句檢查必要性，再考慮畫面交代、縮句及移位。優先放在歌詞空隙，不能因間奏存在就填滿。必要時比較無口白、空隙口白與歌聲下低量口白；這些版本只在本次選定的試剪範圍內製作，不自動增加交付。

歌曲為主、口白為輔是混音意圖；不固定套歌曲 60%／口白 20%。關鍵資訊要可聽懂，不能一律壓低再靠字幕補救。口白補繁體單行、畫布置中的字幕，避免與大量歌詞文字同時爭搶閱讀。ASR 未校對內容不直接當正確歌詞燒入。

## 4. 剪輯與可恢復聲音

每段記錄來源、來源範圍、成片位置與理由。保留原始初剪、必要母版、其他作品與人工修改。不得為湊長度任意倍速、刪斷話語或補造未發生的情節。

預設直覺音軌配置：
- A1 歌曲人聲：立體聲一軌。
- A2 歌曲伴奏：立體聲一軌。
- A3 選用口白：依來源使用單聲道或立體聲。
- A4 原始同期聲：完整保留、預設靜音，可恢復。

配置依本作來源調整，不憑表格增加不存在的分軌。對所有入選畫面保留相同來源範圍的原始聲音與可延伸來源；處理後口白另軌，未使用原聲只靜音／停用，不丟棄或變成無法叫回的靜音檔。

優先一項聲音一條立體聲軌。交接只能拆左右單聲道時，先說明原因、聲道分配、聲像、連結及修改方法，取得對此備案的確認。左右軌不能只是複製同一完整立體聲後相加。首次 DRT 的 L/R 拆軌有量測證據；v02 已核對原生時間線的四條 stereo 音軌、左右聲道 [1,2]、30段原聲同源同位與靜音，並原生匯出 DRT。這支持原生建立與匯出，使用者之後已確認三份交付及限定 DRT 的 callback 修訂可用；這是案例整體確認，不外推為全部效果可編輯或逐項恢復操作都已測過。

有降噪時比較來源與處理後副作用；靜音軌保留原音，不以處理檔冒充來源。

## 5. 檢查與交付

預設檢查檔案存在、來源與範圍、影格率／總長、音訊聲道、選定字幕、原聲靜音及可恢復狀態。技術設定與實際畫面、完整聽感、使用者情緒驗收分開記錄。不要因自檢而默認開啟／匯入／渲染使用者未選擇的應用程式驗證。

DRT 必要製作只在獨立交接工程進行，不切改使用者正在編輯的時間線。Live Save 可能自動持久化變更，未呼叫 SaveProject 不代表現有工程未被保存。助手重新匯入 DRT、播放或另外輸出驗證片，都須有明確操作選擇；未選擇時交付檔案，由使用者匯入。

建立工程後讀回實際影格率，對比保存檔與預覽。若工具設定未生效，先修正或提出可驗證的備案並揭露影格率差異；避免只看參數回傳就宣稱一致。

對字幕與效果，分別記錄原生可改字、圖卡／透明影片素材、獨立字幕檔。建立時讀回 Text+ 成功，不代表保存或 DRT 匯出後仍可改字；無法在授權範圍核對時明確標示，不擅自增加回匯測試。本案例限定 DRT 修訂的結尾字幕為透明素材，不宣稱是原生文字。

若製作中遇到不能在既有授權內解決的工具限制，保存已完成資料並提出具體選項；不連續擴大操作重試。輸出檔需附必需的衍生音訊／素材位置，說明哪些需保持或重新連結；DRT 不能被說成已包含全部來源媒體。

只整理、保存回饋時只寫文件，不修改工程或重新輸出。當使用者要重測，先沿用已確認素材與偏好，回到本輪交付選擇與剪法確認，不重做無必要的素材分析。

## 6. 每輪記錄與完成條件

在忽略版本庫的 production-work 下保存需求卡、交付複選、操作範圍、方案與使用者確認、來源決策、產物及驗收。私人路徑、逐字稿、角色與工具臨時 ID 不寫入通用技能。

建議狀態：待交付選擇 → 素材分析／提案 → 待剪法確認 → 剪輯 → 範圍內檢查 → 交付 → 使用者驗收。交付已明確時可直接進分析；方向或產物變更則只重開受影響決策。

文件格式與引用驗證只支持「保存有效」；本案例的使用者確認另記證據。新增行為與未測分支仍須實際驗證：[MV 回歸測項](TEST_CASES.md)。不得將首輪成片能讀、DRT 存在，推論為流程遵循、單軌立體聲、完整觀看效果都通過。
